API guide

GraphQL in Flaxon

Design, expose, test, secure, and operate a production GraphQL API with Flaxon. This guide covers the native schema engine, HTTP endpoint, GraphiQL, Altair, client integration, and production boundaries.

Flaxon provides: schema types, fields, nested resolvers, queries, mutations, variables, JSON responses, GraphiQL, and Altair playgrounds. Authentication, authorization, persistence, rate limits, and observability remain application responsibilities.

When to use GraphQL

GraphQL is useful when clients need different projections of related data, mobile clients need fewer round trips, or a stable schema contract is more valuable than many resource-specific URLs. Use REST when cacheability, simple public resources, or file delivery is the primary concern. Flaxon supports both styles in one application.

Install and enable

python -m pip install -e .
flaxon run app:app --reload
from flaxon import Flaxon
from flaxon.graphql import GraphQLSchema

app = Flaxon("my-api", debug=False)
schema = GraphQLSchema(query=Query, mutation=Mutation)
app.enable_graphql(schema, url="/graphql", enable_playground=True)

The default API endpoint is /graphql. When playgrounds are enabled, GraphiQL is at /graphql/graphiql and Altair is at /graphql/altair.

Request and response shape

{
  "query": "{ viewer { id login } }",
  "variables": {},
  "operationName": null
}
{
  "data": { "viewer": { "id": 1, "login": "ada" } }
}

Execution errors are returned in an errors array. A valid GraphQL request normally uses HTTP 200 even when execution has errors; reserve HTTP status codes for transport and infrastructure failures.

Types, fields, and nested resolvers

Flaxon uses ObjectType with a field dictionary. Python types provide basic scalar declarations. Use List(Type) for collections and a resolver when a field needs arguments, joins, authorization, or asynchronous work.

from flaxon.graphql import Field, List, ObjectType

Post = ObjectType("Post", {
    "id": Field(int),
    "title": Field(str),
})

User = ObjectType("User", {
    "id": Field(int),
    "login": Field(str),
    "posts": Field(List(Post), resolver=resolve_user_posts),
})

def resolve_user_posts(parent, args, context, info):
    return repository.posts_for_user(parent["id"])

Queries and mutations

def resolve_repository(parent, args, context, info):
    return repository.get(args["id"])

Query = ObjectType("Query", {
    "repository": Field(Repository, args={"id": int}, resolver=resolve_repository),
    "repositories": Field(List(Repository), resolver=resolve_repositories),
})

def resolve_create_repository(parent, args, context, info):
    return repository.create(
        name=args["name"],
        description=args.get("description", ""),
        actor=context["request"].state.user,
    )

Mutation = ObjectType("Mutation", {
    "createRepository": Field(
        Repository,
        args={"name": str, "description": str},
        resolver=resolve_create_repository,
    ),
})

Variables and aliases

query RepositoryPage($id: Int, $term: String) {
  selected: repository(id: $id) { name owner { login } }
  repositories(search: $term) { name stars }
}
{"id": 1, "term": "flaxon"}

Declare argument types on every field. Flaxon coerces declared scalar arguments before calling resolvers. Keep resolver output shaped like the declared type and return None for missing optional records.

Custom scalars

from flaxon.graphql import DateTime, ID, JSON

Audit = ObjectType("Audit", {
    "id": Field(ID),
    "createdAt": Field(DateTime),
    "metadata": Field(JSON),
})

Authentication and authorization

GraphQL does not replace identity or permission checks. Attach the authenticated request to context through normal Flaxon middleware and enforce authorization inside every resolver that reads or changes protected data.

def resolve_private_repository(parent, args, context, info):
    request = context["request"]
    user = getattr(request.state, "user", None)
    if user is None:
        raise GraphQLError("Authentication required")
    repo = repository.get(args["id"])
    if not permissions.can_view(user, repo):
        raise GraphQLError("Not authorized")
    return repo

Check ownership and action permissions at the resolver boundary. Do not rely on hiding fields in the UI. Apply CSRF protection when browser cookies authenticate mutations, use HTTPS, and configure an explicit origin policy.

Persistence, transactions, and N+1 queries

Resolvers should call a repository or service layer, not mutate process-global lists in production. Use the configured database adapter, transactions around mutations, indexes for lookup fields, and pagination for collections. Add request-scoped batching or a data-loader pattern where nested fields would otherwise create N+1 queries.

Limits and abuse controls

  • Limit query depth, aliases, field count, and estimated complexity.
  • Cap collection page sizes and use cursors for large datasets.
  • Rate-limit by authenticated user and client address.
  • Disable public introspection and playgrounds unless intentionally exposed.
  • Set body-size, resolver, and total request timeouts.

Errors and observability

Return stable messages without secrets or SQL details. Log a request ID, operation name, actor, resolver timing, database timing, and error classification. Redact variables containing tokens or passwords. Measure request count, latency, errors, depth, complexity, and cache hits.

Deployment checklist

flaxon run app:app --host 0.0.0.0 --port 8000
curl -fsS https://api.example.com/health
curl -fsS https://api.example.com/graphql \
  -H "content-type: application/json" \
  --data '{"query":"{ __typename }"}'

Put TLS termination, compression, request limits, and access logs at the edge. Use shared sessions, database access, caches, task state, subscriptions, and rate limits before running multiple workers.

Browser JavaScript

async function graphql(query, variables = {}) {
  const response = await fetch("/graphql", {
    method: "POST",
    headers: {"content-type": "application/json"},
    credentials: "include",
    body: JSON.stringify({query, variables}),
  });
  const payload = await response.json();
  if (payload.errors) throw new Error(payload.errors[0].message);
  return payload.data;
}

Python client

import httpx

query = "query($id: Int) { repository(id: $id) { name stars } }"
response = httpx.post(
    "https://api.example.com/graphql",
    json={"query": query, "variables": {"id": 1}},
    headers={"authorization": "Bearer TOKEN"},
    timeout=10,
)
response.raise_for_status()
payload = response.json()
if payload.get("errors"):
    raise RuntimeError(payload["errors"])
print(payload["data"])

Mobile and PWA clients

Use the same HTTPS endpoint from Kotlin, Swift, Flutter, React Native, or a Teloce-Py PWA. Store tokens in platform credential storage, use persisted operations in production, handle offline and partial-data states, and never ship database credentials in a client.

Caching and persisted operations

Cache public immutable queries at the edge where safe. For private data, key caches by user and authorization scope. Persist approved query documents by hash and reject arbitrary production queries when an allowlist is required.

Endpoint and failure-path tests

from flaxon.testing import TestClient

def test_repository_query(app):
    client = TestClient(app)
    response = client.post(
        "/graphql",
        json_data={"query": "{ repository(id: 1) { id name owner { login } } }"},
    )
    assert response.status_code == 200
    assert response.json()["data"]["repository"]["name"] == "flaxon"

def test_graphql_errors_are_structured(app):
    response = TestClient(app).post(
        "/graphql", json_data={"query": "{ unknownField }"}
    )
    assert response.status_code == 200
    assert response.json().get("errors")

Release coverage

  • Authorized, unauthorized, missing, and invalid records for every operation.
  • Variables, defaults, aliases, nested lists, null values, and scalar coercion.
  • Transaction rollback and concurrent mutation behavior.
  • Depth, complexity, body size, timeout, and rate-limit boundaries.
  • Schema snapshots and client compatibility for breaking changes.
  • Browser CORS, cookies, CSRF, and mobile token refresh workflows.

Admin in production

Flaxon Admin is a server-rendered management surface for application models and operations. It is not a replacement for your identity provider, mail service, object storage, job worker, or monitoring platform. Configure those boundaries explicitly before deployment.

What the Admin provides

  • Cookie-backed login/logout, password policy validation, reset and verification tokens, and TOTP MFA with recovery codes.
  • User editing, deactivation, deletion, roles, permissions, protected system roles, and permission-aware CRUD.
  • Model list/detail/create/edit/delete, global search, filters, sorting, pagination, and CSRF-protected bulk actions.
  • Media upload, folders, metadata, hashing, validation, signed URLs, resumable uploads, and thumbnail job integration.
  • Activity, hash-chained audit verification, notifications, operations, settings, CSV/JSON import and export, and CMS workspaces.

Production bootstrap

import os
from flaxon import Flaxon
from flaxon.admin import AdminConfig, AdminDashboard

app = Flaxon("backoffice", debug=False)
admin = AdminDashboard(
    app,
    url_prefix="/admin",
    config=AdminConfig(site_title="Operations", timezone="UTC"),
    storage_path="var/admin.sqlite3",
    redis_url=os.environ.get("REDIS_URL"),
    users=[{
        "username": "owner",
        "password": os.environ["FLAXON_ADMIN_PASSWORD"],
        "roles": ["administrator"],
    }],
)

Use a database-backed Admin store for PostgreSQL/Neon deployments. Apply migrations before starting web processes and workers. A process-local session backend is for development only.

Redis and multiple workers

admin = AdminDashboard(
    app,
    storage_path="var/admin.sqlite3",
    redis_url=os.environ["REDIS_URL"],
    redis_protocol=2,
    redis_max_connections=100,
    session_idle_timeout=1800,
)

Redis-backed configuration coordinates sessions, Admin request limits, publishing locks, and optional WebSocket fan-out. Configure TLS, authentication, pooling, and a protocol version tested with the deployed Redis client.

Passwords, reset mail, and MFA

async def send_reset(identifier: str, token: str) -> None:
    await mail.send(
        to=identifier,
        subject="Reset your Admin password",
        body=f"https://admin.example.com/admin/password-reset?token={token}",
    )

admin = AdminDashboard(
    app,
    password_reset_sender=send_reset,
    require_email_verification=True,
)

Queue delivery instead of blocking a request on a mail provider. Enable distributed rate limits for reset and MFA endpoints when multiple workers are used. Never log passwords, MFA secrets, or recovery codes.

Model lists and custom models

from flaxon.admin import admin_model

@admin_model(
    list_display=["id", "name", "price", "active"],
    search_fields=["name", "sku"],
    list_filter=["active", "category"],
    ordering=["name"],
)
class Flower:
    ...

# Example URLs:
# /admin/flower?q=rose
# /admin/flower?filter_category=Bouquets&order_by=-price&page=2

Server-side permissions remain authoritative. Custom clients must handle 401, 403, validation errors, loading states, and retry states; hidden buttons are not security.

Media and operations

Use S3-compatible storage for private or large files, signed URLs for controlled access, antivirus scanning, EXIF policy, content hashing, upload limits, and durable background thumbnail workers. Use the operations page for visibility, but send serious errors to an external logging and alerting platform.

CSRF and custom pages

<input type="hidden" name="_csrf" value="{{ dashboard.csrf_token() }}">
@app.get("/admin/reports")
async def reports(request):
    user = await admin.auth.current_user(request)
    admin.auth.authorize(user, "admin:read")
    return await admin.jinax.render_response(
        "admin/reports.html",
        {"dashboard": admin, "models": admin.registry.get_all()},
    )

For reusable custom areas with their own routes, templates, static files, hooks, and CLI commands, use FlaxonModule and admin.mount_module(). See the Modules guide.

Deployment checklist

  • Run Admin migrations and use durable database or Redis sessions.
  • Use secret-managed passwords, MFA, secure cookies, TLS, and a trusted public origin.
  • Configure object storage, signed URLs, antivirus, upload limits, and thumbnail workers.
  • Define audit retention, external log export, health checks, metrics, and alerts.
  • Test denied permissions, CSRF rejection, invalid imports, browser workflows, and multi-worker behavior.

For endpoint details, see the Admin API. For service-owned databases and the control plane, see Microservices.
